# work-report

Плагин Claude Code: карточки выполненных задач за день и недельный отчёт по регламенту.
Источники — git-коммиты и история сессий Claude Code (и claude-mem, если установлен).
Карточки можно отправить в таск-трекер (Metrix Tasks) — только после вашего подтверждения.
Пароли, токены, ключи и cookie маскируются ещё до того, как выжимка попадает в Claude.

## Установка
```
/plugin marketplace add yer9ali/work-report
/plugin install work-report@work-report
```
Или из терминала: `claude plugin marketplace add yer9ali/work-report` и
`claude plugin install work-report@work-report`. Затем перезапустите Claude Code.

Обновление вручную:
```
/plugin marketplace update work-report
/plugin update work-report
```
Затем перезапустите Claude Code. Для сторонних маркетплейсов автообновление по умолчанию
выключено. Чтобы обновления приходили сами, включите его: `/plugin` → Marketplaces →
work-report → Enable auto-update. Если вышла новая версия, `/work-report` скажет об этом в
начале ответа.

## Вызов
- `/work-report` — карточки за сегодня;
- `/work-report 2026-10-06` — карточки за указанный день;
- `/work-report push [2026-10-06]` — отправить карточки дня в трекер;
- `/work-report week` — недельный отчёт по регламенту.

При конфликте имён используйте `/work-report:work-report`.

## Конфиг (необязателен)
Свои коммиты определяются по `git config user.email` репозитория. Если коммитите и с другого
email, добавьте его в `~/work-reports/config.json`: `{"authors": ["old@example.com"]}`.
Там же можно задать `reports_dir`, `extra_repos` и `exclude_paths`.

## Регламент компании
В плагине лежит общий пример регламента. Свой положите в `~/work-reports/reglament.md` —
режим `week` будет писать отчёт по нему. Из Word на macOS:
```
textutil -convert txt -output ~/work-reports/reglament.md "Еженедельная отчетность.docx"
```
Файл остаётся только у вас и в репозиторий не попадает.

## Продукты
Отчёт группируется по продуктам. По умолчанию продукт = имя репозитория. Если в отчёте он
называется иначе, скилл спросит один раз и запишет в `~/work-reports/products.json`:
`{"pos_backend": "POS"}`. Номер задачи `[#142]` берётся из карточки, отправленной
в трекер, иначе — из имени ветки или текста коммита.

## Таск-трекер
Нужен личный токен трекера (`mtx_pat_…`): `export TASK_TRACKER_TOKEN=mtx_pat_…` в `~/.zshrc`.
После этого перезапустите Claude Code. Без токена скилл ничего не отправляет и подскажет, что
сделать. Токен никуда не записывается; в чат его не вставляйте.
Задачи создаются со статусом `backlog` на вас; перед отправкой скилл показывает список и
похожие уже существующие задачи. Соответствие продукт → клиент/продукт трекера —
`reference/tracker.json`; новые скилл спросит и запишет в `~/work-reports/tracker.json`.
Номер созданной задачи `[#id]` дописывается в карточку и попадает в недельный отчёт.

## Где журнал
В `reports_dir`: `<дата>.md` — карточки дня, `week-<понедельник>.md` — недельный отчёт,
`products.json` — словарь продуктов, `tracker.json` — свои продукты трекера,
`reglament.md` — регламент компании.
