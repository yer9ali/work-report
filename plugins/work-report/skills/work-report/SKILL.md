# work-report

Аргументы: `$ARGUMENTS` — пусто (сегодня), дата `YYYY-MM-DD` или `week`.

Скрипт: `python3 "${CLAUDE_PLUGIN_ROOT}/skills/work-report/scripts/digest.py"`.
Журнал: `reports_dir` из `~/work-reports/config.json` (по умолчанию `~/work-reports`).

Коды выхода скрипта: 0 — успех; 2 — неверные аргументы (дата не `YYYY-MM-DD`, `--from` позже
`--to`, неизвестная `--tz`); 3 — конфиг не JSON-объект.

## 0. Конфиг (необязателен)
Свои коммиты определяются по `git config user.email` каждого репозитория — конфиг не нужен.
Если коммитов в выжимке нет, хотя пользователь коммитил (другой email на другой машине),
запусти скрипт с `--suggest-authors`, спроси, какие «Имя <email>» — его, и допиши их в
`authors` файла `~/work-reports/config.json`. Остальные необязательные поля:
`reports_dir` (по умолчанию `~/work-reports`), `extra_repos` (репозитории без сессий
Claude Code), `exclude_paths` (игнорируемые пути; `~/.claude-mem` исключён всегда).

## 1. Режим «день» (нет аргумента или дата)
1. Дата = аргумент или сегодня. Запусти `digest.py --from <дата> --to <дата>`.
2. Сгруппируй работу в **крупные задачи**: одна карточка — один законченный результат;
   связанные коммиты и сессии одной темы — в одну карточку; мелочи — в соседнюю.
   Результат, а не процесс («сделано X», а не «работал над X»).
3. Формат каждой карточки — ровно такой:
   ```
   **Заголовок:** <короткий результат>
   **Описание:**
   Что сделать: <что сделано/что требовалось>
   Зачем: <проблема, которую это решает>
   Как проверить: <ручки, тесты, ID, ответы систем из выжимки>
   ```
4. Незаконченное (нет merge, тест красный, ждём ответа) — допиши в заголовок «(в работе)»
   и строку `Осталось: …`.
5. Покажи карточки. Сохрани в `<reports_dir>/<дата>.md` (заголовок `# <дата>`); если файл
   есть — спроси: перезаписать или дополнить.

## 2. Режим «неделя» (`week`)
1. Неделя: пн–пт текущей недели; в сб, вс и пн — только что закончившейся (отчёт сдаётся
   за прошедшую неделю, даже если опоздал).
2. Прочитай `<reports_dir>/<дата>.md` за каждый день пн–пт. Для отсутствующих дней запусти
   `digest.py` за этот день и скажи, какие дни добраны так.
3. Прочитай регламент — `<reports_dir>/reglament.md`, а если его нет, `reference/reglament.md` —
   и напиши отчёт строго по нему: три поля, группировка по
   продуктам, не более 5 пунктов на продукт в «сделано» и «планах», строка ≤ ~160 символов.
   Продукт — заголовок группы из выжимки; если это имя репозитория, а в отчёте продукт
   называется иначе, спроси один раз и допиши `{"репо": "Продукт"}` в `<reports_dir>/products.json`.
   Номер задачи `[#142]` бери из имени ветки или сообщения коммита (`#142`, `142-…`,
   `task-142`); если номера нет — `[#…]` и просьба пользователю вписать.
4. «Планы» — из незаконченного за неделю (и строк «дальше» claude-mem, если есть).
   «Проблемы и блокеры» — только реальные препятствия, каждый из четырёх элементов; если
   «От кого»/«До» неизвестны — `___` и явная просьба пользователю заполнить до сдачи.
5. Сохрани в `<reports_dir>/week-<понедельник>.md`.

## Чего не делать
- **Никогда** не переносить в карточки и отчёт пароли, токены, ключи, персональные данные.
- Не отправлять ничего в таск-трекер — только текст.
- Не выдумывать работу, которой нет в выжимке или дневных файлах.
